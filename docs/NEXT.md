## 1. 처음 켜면 시연을 보여 준다

**정해진 것.** 처음 실행하면 빈 화면 대신 시연이 재생된다. 보여 줄 것은 두 가지다.

- 대화에 따라 화면이 어떻게 만들어지고 고쳐지는가 (일정표, 경로, 결정 카드, 입력 카드)
- 주제가 늘어날 때 분류가 어떻게 자동으로 생기고 정리되는가

**설계 메모.**

- 키 없이 도는 시연 대본이 이미 있다 (`src/llm.rs`의 `SCENES`, `LYBOARD_DEMO`). 이것을 첫 실행 화면으로 꺼낸다.
- 지금 대본은 세 장면뿐이고 분류가 생기는 장면이 없다. 대본을 다시 쓴다: 서로 다른 주제 대여섯 개를 이어서 말하고, 다섯 번째쯤에서 분류가 생기고, 마지막에 "내 차례"로 결정이 찾아오는 흐름. 60~90초.
- 사용자가 친 것처럼 왼쪽 대화창에 입력이 한 글자씩 나타나게 한다. 무엇을 말했더니 무엇이 생겼는지가 보여야 한다.
- 화면 한쪽에 "건너뛰기"와 "내 키로 시작하기". 시연이 끝나면 키 입력 칸으로 넘어간다.
- 시연이 끝난 뒤에도 다시 볼 수 있게 한다 (초기화 옆에 "시연 보기").
- 빈 보드에는 예시 버튼 세 개를 둔다 ("주말 여행 계획", "이번 주 할 일 정리", "회의 준비").

## 2. 비용: 모델을 고를 수 있게 하고, 일에 맞는 모델을 쓴다

**정해진 것.** 모델을 설정에서 고를 수 있게 한다. 기본값은 Opus 5.5. 간단한 일은 더 싼 모델로 돌린다. 지금까지 쓴 돈은 약 6달러.

**설계 의견 (사용자가 고민해 보라고 한 부분).**

역할마다 모델을 따로 둔다.

| 역할 | 하는 일 | 권하는 기본값 | 이유 |
|---|---|---|---|
| 메인 | 사용자의 말을 받아 화면을 고친다 | 요청의 난이도에 따라 고른다 (아래) | 가장 자주 돌고, 대부분은 쉬운 일이다 |
| 작업자 | 작업 지시서를 받아 코딩·조사를 한다 | Sonnet 5.5, 어려우면 Opus 5.5 | 실제로 어려운 일은 여기서 한다 |
| 기억 정리 | 턴마다 남길 사실을 고른다 | Haiku 5.5 (지금도 그렇다) | 짧고 단순하다 |
| 구성 정리, 작업 결과 정리 | 프로그램이 스스로 시작하는 턴 | Haiku 5.5 또는 Sonnet 5.5 | 사용자가 기다리는 턴이 아니다 |

- **작업자를 Haiku로 하자는 안에는 반대 의견이다.** 메인이 하는 일(화면 구성)은 자주 돌지만 쉬운 편이고, 작업자가 맡는 일(코딩, 여러 파일 조사)이 더 어렵다. 싼 모델은 작업자가 아니라 메인의 쉬운 턴에 쓰는 것이 맞다. 작업자를 싸게 하면 결과가 틀려서 다시 시키는 비용이 더 든다. 다만 "파일 정리", "폴더에서 개수 세기" 같은 단순 작업은 Haiku로 충분하므로, 메인이 지시서를 쓸 때 난이도를 함께 정하게 한다 (지금 `job_start`의 `effort`를 모델 선택으로 넓힌다).
- **메인의 모델은 Jev가 이미 내는 판단으로 고른다.** 턴마다 Jev가 "필요한 생각의 깊이"를 low / medium / high로 낸다 (약 0.2초). low → Haiku 5.5, medium → Sonnet 5.5, high → Opus 5.5. Jev 키가 없으면 설정한 기본 모델 하나로 돈다.
- **주의: 모델을 바꾸면 캐시가 깨진다.** 지시문과 도구 정의(큰 부분)가 모델별로 따로 캐시된다. 턴마다 모델이 바뀌면 캐시 적중이 떨어져서 오히려 비쌀 수 있다. 재 보고 정한다. 한 가지 방법은 "최근에 쓴 모델을 유지하다가, 난이도가 두 단계 이상 다를 때만 바꾼다"이다.
- **먼저 잰다.** 지금은 턴당 얼마가 드는지 모른다. 턴마다 모델, 입력·캐시·출력 토큰, 추정 금액을 `data/cost.log`에 남기고, 상태 줄에 "이번 턴 / 오늘" 금액을 보여 준다. 모델별 단가는 설정 파일에 둔다 (바뀌므로 코드에 박지 않는다).
- **보내는 양을 줄인다.** 매 턴 입력이 2만~3만 토큰이다. 줄일 곳: 보드를 줄여 보내는 기준(지금 12,000자)을 낮추기, 그 턴에 쓰지 않을 도구 정의 빼기(대화만 하는 턴에 작업 도구 20개가 다 간다. 단, 도구 목록이 바뀌어도 캐시가 깨지므로 묶음을 두세 가지로만 나눈다).
- **설정 화면.** 역할별 모델, 난이도에 따라 자동으로 고르기 켬/끔, 하루 한도(넘으면 알림).

**정하지 않은 것.** 싼 모델로 화면 구성 품질이 얼마나 떨어지는지. 같은 대화 10개를 세 모델로 돌려 화면을 비교해 보고 기본값을 정한다.

## 3. 키: API 키 말고도 쓸 수 있게

**정해진 것.** API 키를 넣거나, 이미 있는 Claude 설정을 쓸 수 있게 한다.

**설계 메모.**

- 지금도 환경 변수 `ANTHROPIC_API_KEY`가 있으면 그것을 쓴다. 첫 화면에서 "환경 변수의 키를 찾았습니다"라고 알려 주면 된다.
- **Claude Code 엔진 (2026-11-13 구현, `src/cc.rs`).** 키 창에서 "Claude Code"를 고르면 턴마다 `claude -p --output-format stream-json`을 돌려 글자를 받아 그린다. ALI 자체 도구는 ALI 안의 로컬 MCP 서버(127.0.0.1, 실행마다 바뀌는 암호)로 내준다.
  - 이 PC에서 실제로 확인한 것: 창에서 고르고 저장, 화면 그리기, Claude Code 도구로 명령 실행, 사용자의 훅·MCP·CLAUDE.md 적용, 비용·한도 표시, MCP로 경로 찾기(카카오 교통 반영)와 기억 노트 쓰기.

  - 주의: `--tools`에서 ToolSearch를 빼면 MCP 도구 설명이 전부 실려 턴당 39만 토큰이 된다.
  - 2026-11-13 추가 확인: 멈춤 버튼(4초에 멈춤, 남는 프로세스 없음), 답하는 중에 덧붙인 말(다음 턴으로 이어짐), 붙인 사진(Claude Code가 파일로 읽음), Claude Code가 없을 때의 안내 문구, MCP 서버(암호 없거나 틀리면 401, 127.0.0.1 에만 열림, 내주지 않은 도구는 거절, 판 읽기·작업 목록·노트 찾기 응답), 권한 선택(기본에서는 파일 쓰기가 거절되고, 키 창에서 "파일 수정"으로 바꾸면 만들어짐).

  - API 엔진 쪽: 사용자 지시 파일(`instructions.md`), MCP 연결.

  - Claude Code를 뒤에서 실행해서 그것을 통해 대화한다 (공식 CLI나 Agent SDK를 거친다). 구독으로 돌기 때문에 사용자는 따로 돈을 내지 않는다. 대신 지금의 직접 호출 구조(줄 단위 스트리밍, 도구 루프)를 그쪽 방식에 맞춰 한 벌 더 만들어야 한다.

## 5. Mac

**정해진 것.** Mac에서도 되게 한다. Windows의 보안 경고(서명)는 나중에 한다.

**2026-11-12 Mac(Apple Silicon, macOS 26)에서 한 것.**

- 빌드·테스트(20개) 통과. 코드 수정 없이 컴파일됐다.
- `run.sh` (Windows의 `run.ps1`과 같은 build / test / pack). `pack`은 `portable/ALI/ALI.app`을 만들고 임시 서명(ad-hoc)을 붙인다. Info.plist에 마이크 권한 문구를 넣었다.
- `.app` 안에서 실행하면 키·`data/`·`vault/`를 `ALI.app` 옆 폴더에서 찾는다 (`sys::base_dir`).
- 글꼴: AppleGothic 대신 Apple SD Gothic Neo (보통·굵게). 전에는 Mac에 굵은 글꼴이 없었다.
- 음성(`say`): 한글 문장은 설치된 한국어 목소리(유나 우선)로 읽는다. 시스템 기본 목소리가 영어여도 된다.
- 보이지 않는 창으로 카카오맵 읽기: Mac에서 된다 (강남역→판교역 15.7km·26분을 읽어 옴).
- 화면 안의 브라우저(wry): Mac에서는 창 아래쪽 기준 좌표라서, 창 크기가 바뀌면 웹 카드 위치를 다시 맞추게 했다.
- 상단바 색: Mac은 시스템 다크 모드를 따른다 (손대지 않음).

**Mac에서 아직 확인하지 못한 것.** 실제 API 키로 도는 턴, 웹 카드가 카드 자리에 정확히 붙는지(확대·축소·창 크기 바꾸기 포함), 마이크 권한 요청과 마이크 대화, 스피커 소리, 다른 Mac에서 `.app` 열기.

## 2026-11-12~13에 Mac에서 더한 것

- **음성 대화:** 마이크를 늘 열어 둔다. AI가 말하는 중에 사용자가 말하면 바로 멈추고 듣는다(스피커 소리보다 뚜렷이 큰 소리가 0.2초 이어지면). "그만", "멈춰", "stop"은 말과 일을 모두 멈춘다. 스피커에서 나온 자기 목소리를 받아쓴 것은 버린다.
- **기다리기:** "잠깐만", "확인해 볼게", "hold on"이라고 하면 부를 때까지 말하지 않고 진행하지 않는다. 그동안 들린 말은 작은 모델(Haiku)이 나를 부른 말인지 판단한다. "알리", "다 봤어"는 바로 깨운다.
- **소리로 하는 대답은 턴마다 한 번:** 카드를 먼저 올리고 끝에 `tell` 하나로 정리한다. 일 시작 전 `say`는 아직 아무 말도 안 했을 때만 읽는다.
- **되묻기:** 가리키는 것을 모르면 "기록에 없네요" 대신 맥락으로 후보를 추려 decision 카드로 묻는다.
- **조사도 작업자에게:** 웹 검색이 세 번 넘게 필요한 조사는 맡긴다.
- **시간 기록:** 턴마다 `data/timing.jsonl` (받아쓰기, 판단 모델, 첫 화면, 첫 소리, 도구별 시간, 토큰).
- **진행 표시:** 쓰고 있는 카드 이름과 줄 수를 보여 준다.
- **밝은 화면:** OS 설정을 따르고, 왼쪽 아래 "밝게/어둡게"로 바꾼다 (`data/theme.txt`).
- **대화 언어:** 왼쪽 아래 "English/한국어". AI의 대답, 카드, 받아쓰기 언어가 바뀐다 (`data/lang.txt`). 화면 글자는 아직 한국어다(4번).
- **문자·전화 (Mac):** `contact_find`, `message_send`, `phone_call`, `message_read`. 보내기와 걸기는 확인 카드에서 사용자가 눌러야만 프로그램이 직접 한다(`src/phone.rs`). 작업자는 못 쓴다.

**정하지 않은 것.** 음성 대화 중에 생각 깊이를 낮음으로 고정할지 (콘셉트 15개 제안 턴에서 생각만 34초). 브라우저 작업 보강(페이지 캡처, 글자로 찾아 누르기, 최종 제출 확인). 클라우드 서버 연결(지금도 ssh로 가능, 서버 목록을 기억에 등록하는 방식).

## 하지 않기로 한 것

- **"AI가 묻지 않고 명령을 실행한다"는 그대로 둔다.** 이것을 좋아하는 사람들이 있다. 첫 화면과 README에 분명히 적기만 한다.
- **"가치가 쌓여야 느껴진다"는 따로 손대지 않는다.** 쓸 때 편하면 계속 쓰게 된다.
- **Windows 서명**은 뒤로 미룬다.

- 이름 "ALI"의 상표 확인.
- 릴리스 v0.1.0의 묶음은 2026-11-12 오후 빌드다. 그 뒤에 들어간 것(경로 카드, 그림 카드, 입력 종류, 이름 붙은 값)은 들어 있지 않다.

## 확인하지 못한 채 남은 것

- 실제 마우스 휠과 끌기의 느낌, 마이크 대화, 소리가 실제로 나는지
- 다른 PC에서의 실행, 처음 실행 화면에서 키를 넣고 시작하기
- 작업자별 git 분리 작업 폴더, 진행 중인 작업자에게 말 전하기와 멈추기
- 핵심 기억이 6,000자를 넘었을 때 간추리기
- 이름 붙은 값을 바꿨을 때 실제 화면에서 여러 카드가 함께 바뀌는 모습 (자동 테스트로만 확인)
- 그림 카드에 웹 주소를 줬을 때
